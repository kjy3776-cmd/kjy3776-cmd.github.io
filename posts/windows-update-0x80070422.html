Windows 11 업데이트 오류 0x80070422: 서비스 ‘사용 안 함’ 확인과 복구

2026-09-28 확인·지원 중인 Windows 11 / 개인용 PC 기준Windows Update0x80070422
1분 요약증상 구분해결 순서

Windows Update 화면에서 0x80070422가 뜨면 업데이트 캐시를 지우기 전에 서비스의 시작 유형부터 확인하세요. ‘중지’와 ‘사용 안 함’은 다른 상태입니다.

Microsoft는 이 코드를 서비스가 비활성화돼 시작되지 않는 상황과 연결합니다. 다만 Microsoft Store나 보안 앱 등 다른 화면에서 나온 같은 코드는 이 글의 대상이 아닙니다. 2026년 9월 28일 확인한 공식 문서를 바탕으로 Windows 11 개인 PC와 조직 관리 PC의 조치를 나눴습니다.

1. 1분 해결 요약

  1. 오류가 Windows Update 화면에서 발생했는지 확인하고, 실패한 KB 번호와 Windows 버전을 기록하세요.
  2. 작업을 저장하고 재시작한 뒤 설정 → 시스템 → 문제 해결 → 다른 문제 해결사 → Windows Update → 실행을 사용합니다. Get Help 앱이 열리면 안내를 마치세요.
  3. 서비스 앱에서 Windows Update의 시작 유형을 확인합니다. ‘중지’와 ‘사용 안 함’은 다릅니다.
  4. 본인 소유·관리 PC에서 시작 유형이 실제로 사용 안 함일 때만 수동으로 변경하고 서비스를 시작한 뒤 업데이트를 다시 확인합니다. 회사·학교 PC는 IT 담당자에게 문의하세요.

여기서 멈추세요: 접근 거부, 조직 관리 문구, 변경 후 곧바로 정책에 의해 원래대로 돌아가는 상황이라면 레지스트리·정책 우회를 시도하지 마세요.

2. 증상별 원인표

0x80070422 증상과 다음 조치 비교
보이는 상태가능한 해석맞는 다음 단계
Windows Update에 0x80070422, 시작 유형 ‘사용 안 함’Microsoft가 설명하는 서비스 비활성화와 일치개인 PC에서만 제한적으로 활성화·시작
서비스는 ‘수동’ 또는 일시 ‘중지’그 사실만으로 원인 확정 불가문제 해결사 실행 후 실제 업데이트 결과 확인
서비스 변경이 거부되거나 조직에서 관리관리 권한·조직 정책 가능성정책 우회 없이 IT 관리자에게 전달
서비스를 시작해도 같은 코드 반복다른 구성 요소 또는 시스템 손상 가능성BITS 진단·시스템 파일 검사·공식 지원
Store 또는 보안 앱에서 같은 코드오류가 나온 앱과 서비스가 다름해당 제품의 공식 지원 절차로 이동

표는 좌우로 움직여 전체 내용을 볼 수 있습니다.

위 표는 증상 분류표이지 PC의 고장 원인을 원격으로 확정한 결과가 아닙니다. 설치 오류 0x80070002는 업데이트 파일·캐시 문제를 중심으로 다루므로, 이 코드의 첫 조치인 캐시 삭제를 0x80070422에 곧바로 가져오지 않습니다.

3. 해결 7단계

1단계: 오류가 난 화면과 버전부터 기록

설정 → Windows Update → 업데이트 기록에서 실패한 업데이트의 KB 번호와 오류 표시를 기록합니다. Windows+R → winver로 Windows 버전과 OS 빌드를 확인하세요. 오류가 Store 설치나 다른 앱에 떴다면 이 글의 서비스 변경을 적용하지 않습니다. 회사·학교 계정으로 관리되는 장치라면 서비스 변경 전에 IT 담당자에게 문의할 준비를 하세요.

2단계: 재시작 후 Windows Update 문제 해결사

열린 작업을 저장하고 PC를 다시 시작합니다. 설정 → 시스템 → 문제 해결 → 다른 문제 해결사 → Windows Update → 실행을 열어 Get Help 진단이 시작되면 끝까지 진행하세요. Microsoft는 Windows 11에서 Get Help의 Windows Update 문제 해결사를 우선 안내합니다. 권장 조치를 적용했다면 재시작하고 업데이트 확인으로 같은 코드가 남는지 봅니다.

3단계: ‘사용 안 함’과 ‘중지’를 구분

Windows+R → services.msc를 실행하고 목록에서 Windows Update를 찾아 속성을 엽니다. 시작 유형과 서비스 상태를 따로 읽어 적으세요. 시작 유형의 사용 안 함은 서비스 시작 자체를 막는 설정이지만, 서비스 상태의 중지는 현재 실행 중이 아니라는 뜻입니다. ‘수동’이나 ‘중지’만 보고 무조건 ‘자동’으로 바꾸지 마세요. 서비스가 다시 중지되더라도 실제 업데이트 검색·설치가 성공하면 그 상태만으로 실패라고 단정하지 않습니다.

4단계: 개인 PC에서 ‘사용 안 함’일 때만 제한적으로 변경

본인 소유의 개인 PC이고 관리자 권한이 있으며 3단계에서 시작 유형이 사용 안 함으로 확인된 경우에만, 변경 전 상태를 기록한 뒤 수동 → 적용 → 시작을 선택합니다. Microsoft의 해당 오류 안내는 서비스를 활성화하고 수동으로 시작하도록 권합니다. 이어 설정 → Windows Update → 업데이트 확인을 다시 실행하세요. 서비스가 없거나 시작 버튼이 비활성화되거나 접근이 거부되면 임의 명령·레지스트리 파일로 강제하지 말고 7단계의 지원 경로로 넘어갑니다. 회사·학교 장치는 이 단계의 설정 변경 대상이 아닙니다.

5단계: BITS 등 전송 문제를 공식 진단으로 분리

Windows Update 서비스는 시작됐는데 코드가 반복된다면 Get Help에서 Background Intelligent Transfer Service(BITS) 문제 해결사를 찾아 진단해 보세요. BITS는 업데이트 다운로드와 관련된 별도 서비스이며 Microsoft가 전용 문제 해결사를 제공합니다. 결과를 기록하고 그 안내 범위에서만 조치하세요. 다른 서비스의 시작 유형을 한꺼번에 바꾸거나 스크립트로 업데이트 구성 요소 전체를 초기화하지 않습니다.

6단계: 시스템 파일 손상이 의심될 때만 DISM 다음 SFC

문제 해결사가 구성 요소·시스템 파일 문제를 지적하거나 다른 Windows 기능도 함께 실패한다면, 관리자 명령 프롬프트에서 아래 명령을 한 줄씩 순서대로 실행할 수 있습니다. Microsoft는 DISM을 먼저, SFC를 나중에 실행하도록 안내합니다. DISM은 정상 파일을 얻기 위해 Windows Update에 의존할 수 있어 업데이트 클라이언트가 고장 났다면 이 단계가 실패할 수도 있습니다. 실패 메시지를 기록하고 임의의 다운로드·복구 소스를 지정하지 마세요.

DISM.exe /Online /Cleanup-Image /RestoreHealth
sfc /scannow

각 검사가 끝날 때까지 창을 닫지 않고, 완료 뒤 재시작하여 업데이트를 다시 확인합니다. 0x80070422 자체만으로 시스템 파일 손상을 단정하지 않습니다.

7단계: 공식 지원 또는 현재 버전 복구 재설치 검토

여전히 실패하면 Microsoft 공식 지원에 오류 캡처, KB 번호, winver 결과, 서비스의 시작 유형·상태, Get Help 결과와 DISM·SFC 마지막 메시지를 전달하세요. 개인용 Windows 11에서 공식 지원이 현재 버전 복구를 권하면 설정 → 시스템 → 복구 → Windows Update를 사용하여 문제 해결 → 지금 다시 설치 옵션도 검토할 수 있습니다. Microsoft는 이 기능이 같은 Windows 버전을 다시 설치하며 앱·파일·설정을 보존하도록 설계됐다고 안내하지만, 중요한 파일은 먼저 백업하고 전원·인터넷을 유지하세요. 관리형 PC나 일부 이전 버전·정책 환경에는 옵션이 없을 수 있습니다. 서비스가 계속 ‘사용 안 함’으로 되돌아간다면 복구 재설치보다 관리 정책 여부를 먼저 확인합니다.

4. 정상 확인과 실패 시 다음 조치

  • 설정 → Windows Update → 업데이트 확인이 오류 없이 끝나는지 확인합니다. ‘최신 상태’ 또는 실제 업데이트 목록이 보이면 검색 단계가 진행된 것입니다.
  • 원래 실패한 KB가 있다면 업데이트 기록의 성공 상태와 필요한 재시작 완료를 확인합니다. 단순히 서비스가 잠시 ‘실행 중’으로 바뀐 것만으로 해결됐다고 판단하지 않습니다.
  • 다시 0x80070422가 뜨면 서비스의 시작 유형이 다시 ‘사용 안 함’으로 바뀌었는지 확인하고, 변경 시각과 조직 관리 여부를 공식 지원 또는 IT 담당자에게 전달합니다.

5. 데이터·계정·보안 주의

  • 데이터: 문제 해결·재시작 전에 작업을 저장하고, 복구 재설치 전에는 중요한 파일을 별도로 백업하세요.
  • 계정·권한: 관리자 암호가 없거나 조직이 관리하는 PC라면 서비스·정책을 우회하지 않습니다. 공식 복구는 Microsoft 지원 또는 조직 IT를 통하세요.
  • 보안: 바이러스 백신·방화벽을 끄거나 출처 불명의 ‘업데이트 복구’ 도구, 레지스트리 파일, 일괄 서비스 변경 명령을 실행하지 않습니다.
  • 결제: Windows Update 오류 해결을 위해 유료 원격 수리나 새 라이선스를 즉시 구매할 필요는 없습니다. 지원 연락처는 Microsoft 공식 페이지에서 직접 찾으세요.

6. FAQ

Windows Update 서비스가 ‘중지’이면 무조건 고장인가요?

아닙니다. 현재 상태와 시작 유형은 별개입니다. ‘중지’만 보지 말고 업데이트 확인을 다시 눌러 코드가 재현되는지 확인하세요.

시작 유형이 ‘수동’이면 ‘자동’으로 바꿔야 하나요?

아닙니다. 이 글은 사용 안 함으로 확인된 개인용 PC에서만 수동으로 바꿔 서비스를 시작하는 제한된 절차를 안내합니다. 수동이라는 이유만으로 자동 설정을 강제하지 않습니다.

회사 PC에서 서비스 변경이 거부되면 어떻게 하나요?

조직 정책이나 권한 때문일 수 있습니다. 오류 코드·KB·시작 유형·발생 시각을 IT 담당자에게 전달하고 승인 없이 정책을 바꾸지 마세요.

Microsoft Store에서도 같은 코드가 뜹니다. 이 글을 써도 되나요?

이 글은 Windows Update 화면의 0x80070422에 한정합니다. Store에서 나온 경우는 오류가 난 제품의 공식 지원 절차를 확인하세요.

한 줄 요약
